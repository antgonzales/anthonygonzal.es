In 1974, Vera Molnár created a grid of nested squares with small random
disruptions. She called the series
[(Dés)ordres](https://dam.org/museum/artists_ui/artists/molnar-vera/des-ordres/):
order and disorder at once.

I love this work because, despite being made by a machine, it doesn't really
look machine-made. The squares are too crooked, too uneven. It looks a little
like someone picked up a pen and started drawing squares out of boredom. It
feels human.

In this post, we'll rebuild that effect. The result is a React component of
about a hundred lines that returns an SVG, and the algorithm is small. I followed the [Generative Landscapes
walkthrough](https://generative-landscapes.com/pattern-based-on-vera-molnars-des-ordres-series-1974-algorithm-21-01/),
and adapted it for the browser.

The entire project can be broken down into four steps.

```text
for each cell in the grid:
    1. calculate the center point of the current cell

    for each nested square, from outside inward:
        2. calculate the current square's inward offset
        3. randomly decide whether the current square will be drawn

        if the current square will be drawn:
            4. move each of the current square's four corners by a small random amount
               draw a polygon through the four moved corners
```

## 1. A grid

Molnár's plot is 17×17, but we'll work at 8×8 while building it up so each
step is easier to see, then scale it back up at the end. The SVG draws on a
528-unit square with a little padding around it, divided evenly into cells.

```tsx
const VIEWBOX_SIZE = 528;
const gridSize = 8;

const cellSize = VIEWBOX_SIZE / gridSize;

function placeOnGrid(cellIndex: number) {
  const row = Math.floor(cellIndex / gridSize);
  const column = cellIndex % gridSize;

  return [cellSize * (column + 0.5), cellSize * (row + 0.5)] as const;
}

const cells = Array.from({ length: gridSize * gridSize }, (_, cellIndex) =>
  placeOnGrid(cellIndex),
);
```

For now every square is the same size and shares its edges with its neighbors.
The unevenness comes later.

## 2. Offset inward

Now we copy each square inward, a fixed distance at a time.

Generative Landscapes uses a slightly strange number here: divide the cell
size by 2.01 to define an inward range that stops just short of the center,
then use that range to space the squares. It also uses nine rings per cell,
but I found seven gave me the image I wanted, so adjust the number until it
looks right to you.

```tsx
const CENTER_DIVISOR = 2.01;
const ringsPerCell = 7;
const outerHalfSize = cellSize / 2;

// Ring indices run from 0 to ringsPerCell - 1, so even dividing by a plain 2
// leaves the innermost square a half-size of outerHalfSize / ringsPerCell.
// The 2.01 is not what stops the last square from collapsing to the center.
const ringSpacing = (outerHalfSize * 2) / CENTER_DIVISOR / ringsPerCell;

function offsetInward(ringIndex: number) {
  return outerHalfSize - ringIndex * ringSpacing;
}
```

I kept the 2.01 because it nudges the spacing a touch tighter than dividing by
2 would, which leaves the inner squares slightly larger.

Now we have squares within squares. Perfectly regular, and a little
antiseptic.

## 3. Strike out a third

Next, we'll remove about a third of the squares at random.

```tsx
const REDUCE = 0.35;

function survivesStrikeOut(random: () => number) {
  return random() >= REDUCE;
}
```

We call this once for every square, and the picture starts to get interesting.
Squares drop out at random, so the gaps between rings stop being even while
the grid underneath stays exactly where it was.

There is variation now, but it still looks unmistakably generated.

## 4. Move every corner

This is the step that stops it looking like a grid of squares.

Each corner gets its own small nudge. Not enough to turn the squares into
obvious polygons, just enough that they stop lining up perfectly with one
another.

We need four points we can move separately, which rules out `<rect>` and
means `<polygon>`.

```tsx
const JITTER_SHARE = 0.022;
// `disorder` is a prop. It defaults to 1; the figures above pass 0.
const jitter = JITTER_SHARE * cellSize * disorder;

function moveEveryCorner(
  centerX: number,
  centerY: number,
  halfSize: number,
  jitter: number,
  random: () => number,
) {
  return Array.from({ length: 4 }, (_, cornerIndex) => {
    const isLeftCorner = cornerIndex === 0 || cornerIndex === 3;
    const isTopCorner = cornerIndex < 2;
    const x = isLeftCorner ? centerX - halfSize : centerX + halfSize;
    const y = isTopCorner ? centerY - halfSize : centerY + halfSize;

    const jitteredX = x + (random() * 2 - 1) * jitter;
    const jitteredY = y + (random() * 2 - 1) * jitter;

    return `${jitteredX},${jitteredY}`;
  }).join(" ");
}
```

Each corner can move at most 2.2% of the cell size, which sounds like almost
nothing but turns out to be enough. Push it much further and the squares start
to look deliberately distorted, while at 2.2% the effect only really shows
once several squares sit inside one another.

The outer square might lean one way, while the next one leans another. None of
them looks especially strange on their own. Together, the squares lose the
clean mechanical alignment of the earlier steps.

missing, and just enough wobble to keep the grid from feeling manufactured.

## The same accident twice

The strike-outs and corner nudges are all random, but the randomness comes from
[Mulberry32](https://stackoverflow.com/a/47593316), a small seeded generator,
rather than `Math.random`:

```tsx
// Mulberry32 by bryc, modified by the Stack Overflow community.
// https://stackoverflow.com/a/47593316 — CC BY-SA 4.0
export function createRandom(seed: number) {
  let state = seed >>> 0;

  return () => {
    let value = (state += 0x6d2b79f5);
    value = Math.imul(value ^ (value >>> 15), value | 1);
    value ^= value + Math.imul(value ^ (value >>> 7), value | 61);
    return ((value ^ (value >>> 14)) >>> 0) / 4294967296;
  };
}
```

Determinism matters because I want to be able to look at the same drawing
twice. If I used `Math.random`, the drawing would change on every page load.
Randomness like that makes it hard to tell whether a code change improved the
composition or whether the browser just happened to choose a nicer arrangement.
With a seed, I can keep one version, come back to it after every change, and
know that I'm looking at the same accident each time.

The step-three and step-four figures use the same sequence of random values.
Every square draws its corner offsets whether or not it survived step three,
and when `disorder={0}` those offsets resolve to zero, so the same squares are
removed in both figures and the only difference is whether their corners
wobble.

A plotter would do this naturally: give it the same instructions and it draws
the same thing. The seed gives the browser a similar kind of memory.

## At Molnár's density

The grid size is a prop, so getting up to Molnár's 17×17 takes one number:

What I like about rebuilding (Dés)ordres is how little is actually required.
Start with something rigid. Remove part of it. Make each remaining piece wrong
by an amount small enough to almost escape notice.

The order never disappears. That's what makes the disorder visible.
